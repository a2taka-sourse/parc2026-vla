# PARC2026 VLA fine-tuning notes

ロボット操作のシミュレーション（LIBERO 系）で、Vision-Language-Action モデルを LoRA で適応させた記録です。
Physical AI Robot Challenge 2026（PARC2026）の予選 Track 1 で公式スコア **0.36363** を記録し、本選に進みました。

このリポジトリには、学習・マージ・評価に使った Colab ノートブックと、試した手法の結果を置いています。学習済みの重みは置いていません（下記「ライセンス」）。

## 結果の要約

計19回提出し、スコアを大きく上げたのはバックボーンの交換の1回でした。

| # | 変更 | スコア |
| --- | --- | ---: |
| 1 | 既定値 `n_action_steps`=50 のまま | 0.0 |
| 3 | 画像の180度回転を修正、`n_action_steps`=10 | 0.06545 |
| 5–6 | SmolVLA に LoRA、誤差拡散平滑化 α=0.5 | 0.13178 |
| 7–12 | 画像拡張・タスク40種・重複排除・平滑化の強化・中央値投票 | 0.069〜0.124 |
| **13** | **SmolVLA（0.5B）→ π0.5（3.7B）に交換** | **0.36363** |
| 14–19 | 推論ステップ数・再学習・実行長ゲート・LoRA差分の縮小 | 0.241〜0.311 |

分かったこと：

- **天井はモデルの側にあった。** 手元の未知の摂動24件で、ベース重みと自作 LoRA の結果が24件中23件で一致しました。学習側の工夫では挙動がほぼ動かないと判断し、容量の大きいモデルに乗り換えました。
- **推論時に外から足した制御規則は、5方式すべてで悪化した。** 行動のがたつき（ジャーク）はチャンクの継ぎ目に集中していました。継ぎ目を滑らかにする方式（最平滑の選択、補間、クロスフェード、RTC、学習済みの実行長ゲート）は、どれも新しい観測への反応を遅らせ、成功率を下げました。
- **LoRA の差分は効いていた。** マージ後の重みとベースの差分を75%に縮めると、0.36363 → 0.31137 に下がりました。手元の評価器では検出できなかった寄与を、重みの側から確かめた実験です。
- **スコア0の2回は、どちらも性能と無関係だった。** `n_action_steps`=50（約2.5秒の盲目実行）と、`transformers` の版を固定し忘れたことによる例外です。例外がスコアに出ず、性能不足と見分けがつかない点に注意が要ります。

## 本選（第1ラウンド）の記録

本選は3つの Track に分かれ、Track 1 は既知の環境、Track 2 は未知の環境（視点・配置・ノイズなど）、Track 3 は既知の動作を組み合わせた未知の課題です。第1ラウンドの最終提出と、その前に測った主な結果です。

| Track | 最終提出 | 公式スコア | 予選構成からの変化 |
| --- | --- | ---: | --- |
| 1 | 選別データで追加学習 + 回転だけ平滑化 | **0.4059** | 0.3636 → 0.4059 |
| 2 | 全データで 8,000 step 学習し直した版 | **0.3806** | 0.1064 → 0.3806（3.6倍） |
| 3 | 予選の重みのまま | 0.000 | 4回試して抜け出せず |

第1ラウンドで敗退しました。

### Track 1・2 で分かったこと

- **Track 2 は学習量で伸びた。** 4,500 step で 0.2369、8,000 step で 0.3806 と上がり、12,000 step では 0.2161 に下がりました。学習率が小さくなった後半で悪化しています。
- **手元の評価が Track 2 では逆を向いた。** 公開例題での成功率は予選の重みが 56/80、8,000 step 版が 47/80 でしたが、公式は 0.106 と 0.381 でした。手元の評価だけで採否を決めない、と方針を変えました。
- **データの選別は、効いたとは言えなかった。** 滑らかさの指標（SPARC）でタスクごとに下位20%を除いて追加学習しました。Track 1 は 0.3910 に上がりましたが、Track 1 には比較用の版を出していません。Track 2 では、選別しなかった版（0.3050）と同じ水準（0.2953）でした。
- **平滑化は Track ごとに逆に効いた。** 回転の成分だけを平滑化すると、Track 1 は 0.3910 → 0.4059 に上がり、Track 2 は 0.3806 → 0.2525 に下がりました。再計画の間隔を1に縮めると、両方とも悪化しました。
- 公式の採点は話数が少なく、差の小さい比較（0.39 と 0.41 など）は誤差の範囲だと考えて扱いました。

### Track 3 の4回の試行

課題は、物体を取り出して別の場所に置く動作を組み合わせたもので、学習前のモデルは成功 0/20 でした。ただ、20回中6回は掴んで置くところまで行っており、外れていたのは置き場所と、周りの物に触れてしまうことでした。

公開データには同じ種類の動作がないため、**シミュレータの正確な位置情報を使うスクリプトの「教師」で手本を作り、π0.5 に学ばせる**方針にしました（提出するのは π0.5 + LoRA だけで、タスクごとの分岐は入れていません）。教師は手本50本のうち50本を、周りに触れずにやり遂げました。

| 試行 | 変更 | 結果（手元 20回） |
| --- | --- | --- |
| 1 | 教師の手本を元データと半々に混ぜる | 掴める回数 6 → 2。公式も 0 |
| 2 | 正規化の設定ミス（学習と土台で方式が違った）を直す | ほぼ変わらず |
| 3 | 教師の手本だけで学習 | 周りに触れる回数 16 → 3。ただし運んだまま置けない |
| 4 | 教師を速くし、制限時間の手前で終わる手本だけを使う | 触れる回数 1。置くところまで届いたが、置き場所が外れる |

試行3で、教師そのものが遅すぎたことに気付きました。離すまでに270 step ほどかかり、制限時間を超えた手本も学習データに入っていました。生徒が「置けない」のではなく、「間に合っていない」状態でした。

### Track 3 の反省

- **規模が1〜2桁足りなかった。** 手本は最終的に63本で、しかも課題1つ分だけでした。模倣学習の研究では、環境と物体の組み合わせごとに約50本で頭打ちになり、その先は多様さが効くと報告されています（Data Scaling Laws, arXiv:2410.18647）。少数の手本を位置や物体を変えて大量に増やす方法（MimicGen, arXiv:2310.17596）で、課題と配置を広げるべきでした。
- **教師が姿勢を一度も変えていなかった。** 手本の回転の成分が常に0だったので、生徒は回転を学びようがありません。幅の広い物体を回して掴む課題は、この時点で解けなくなっていました。学習の前に、行動の各成分にばらつきがあるかを確かめるべきでした。
- **教師の質より、生徒が崩れる場面を見ていなかった。** 教師は 63/70 掴めるのに、生徒は 2〜3/20 でした。生徒を走らせて失敗した状態を集め、そこからの立て直しを教師に付け直す手順（DAgger）を回せば、この差を直接埋められました。
- **最初に教師の所要時間を測るべきだった。** 制限時間を超える手本の混入に気付くまで、試行を2回使いました。手本を作る段階で、時間と衝突の条件を評価と同じにしておけば、最初から避けられました。

## 構成（最高スコア）

- ベース: `lerobot/pi05_libero_finetuned_v044`（π0.5、PaliGemma + action expert、約3.7B、bfloat16）
- 学習: action expert のみ LoRA（r=16, α=16）、6,000 step、batch 8、学習率 1e-4→1e-5（コサイン）、画像拡張なし
- データ: `lerobot/libero_plus` から4タスク×60エピソード（独自の収集・生成はなし）
- 推論: `chunk_size`=50 のうち `n_action_steps`=10 を実行して再観測、誤差拡散平滑化 α=0.5
- 環境: Google Colab（A100）、LeRobot 0.6.0 + peft
